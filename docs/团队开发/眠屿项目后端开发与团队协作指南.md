## 一、项目现状与开发目标

### 1.1 当前前端状态

现有代码是一个 **Fake Demo**，位于 `E:\mianyufronted`（已推送至 `Mianyu-Sleep-Isle/mianyu` 的 `feature/fronted` 分支）。

```
lib/
├─ domain/contracts.dart     ← 14个枚举 + 10个DTO + 12个Port（已冻结）
├─ data/fake_services.dart   ← 演示用假数据，集成时要全部替换
├─ app_controller.dart        ← 应用状态编排，只依赖 Port 接口
├─ presentation/screens/      ← 11个页面（已完整实现 UI）
└─ presentation/theme/        ← 主题
```

**关键特征**：前端已经完整定义了所有 Port 接口和 DTO 结构。这是你开发后端的**契约蓝本**——后端必须实现前端已定义的 Port，后端的数据必须符合前端已定义的 DTO。

### 1.2 五模块数据链

```
ContentSelection → SleepIntent → SleepPlan → SceneConfig → SleepSession → MorningFeedback → PreferenceProfile
    (模块1)       (模块2)      (模块2)      (模块3)        (模块4)         (模块5)          (模块5)
```

### 1.3 每个模块要做什么

| 模块 | 成员 | 核心职责 | 前端 Port 依赖 |
|---|---|---|---|
| 模块1 | 内容中心 | 声音/故事/呼吸素材目录、白名单、收藏 | `ContentCatalogPort`、`PlayableResourceResolverPort` |
| 模块2 | 方案决策 | 规则引擎、方案生成与确认 | `PlanComposerPort`、`PlanQueryPort`、`PreferenceQueryPort` |
| 模块3 | 声景创作 | 场景编辑、拖放、保存、冻结 | `SceneConfigQueryPort` |
| 模块4 | 睡眠执行 | 多轨播放、会话记录、事件 | `SleepSessionPort`、`AudioEnginePort` |
| 模块5 | 反馈成长 | 反馈提交、偏好更新、积分 | `FeedbackCommandPort`、`PointLedgerPort` |

**技术选型建议**：
- 后端语言：**Python (FastAPI)** 或 **Node.js (Express/NestJS)**，简单易部署
- 数据库：**SQLite**（MVP 本地优先，课程期够用）
- 存储：`assets/` 音频文件放在后端静态目录或 CDN
- 通信：前端通过 HTTP 调用后端 REST API

> ⚠️ **重要提醒**：技术栈最终由**组长**在集成基线中锁定，所有成员使用统一技术，不得各自选一套。

### 🟢 成员2：睡前沟通与方案决策

**后端工作范围**：

1. **方案生成 API**
   - `POST /plans/compose`：接收 `SleepIntentDto`（情绪、人声偏好、禁忌、可用时长、年龄模式），返回 `SleepPlanDto`
   - 规则引擎逻辑：
     ```
     优先级：儿童限制 > 禁忌 > 不要人声 > 短时间 > 想被陪 > 默认
     
     规则1：不要人声 → soundscape（纯声景）
     规则2：时间≤15分钟 + 焦虑/兴奋 → breath + soundscape
     规则3：想被陪 + 未禁止人声 → story + soundscape
     规则4：儿童模式 → child故事或纯声景
     规则5：默认 → soundscape（稳定环境声）
     ```
   - 四条预制对话结果：
     | 条件 | plan_type | tracks | reason |
     |---|---|---|---|
     | 雨+不要雷 | mix | 轻雨+翻书（无雷）| 你提到不要雷声，已排除 |
     | 15分钟+考试 | breath+soundscape | 呼吸+轻雨 | 时间短、思绪多，先呼吸再留环境声 |
     | 不要人声 | soundscape | 轻雨+壁炉（无人声）| 你说不想听人声，只保留环境声 |
     | 心情不好+想陪 | story+soundscape | 短故事+轻雨 | 你希望有人陪，选了平缓短篇 |

2. **方案查询 API**
   - `GET /plans/current`：返回用户最近一条草稿方案
   - `GET /plans/history`：返回历史方案列表

3. **方案确认 API**
   - `POST /plans/{id}/confirm`：确认方案（校验白名单+审核状态+年龄模式）

4. **偏好查询**
   - `GET /preferences`：返回 `PreferenceProfile`（人声偏好、禁忌标签等）
   - **数据库表**：`preference_profile` + 四张子关系表

**数据校验规则**：
- 儿童模式：禁止使用成人故事、成人专属声音
- 禁忌标签：排除对应素材（雷声 A12 永远被排除）
- 方案音轨的 `asset_id` 必须存在于模块1的白名单中
- 故事 `story_id` 必须 `review_status=approved`
- 方案总时长必须 `> 0`，`fade_out` ≤ 总时长

**禁止事项**：
- ❌ 不直接播放音频
- ❌ 不创建场景配置
- ❌ 不记录睡眠会话
- ❌ 不把对话原文存入数据库
- ❌ 不更新偏好（只读取）

**验收标准**：
- ✅ 四条预制对话生成正确类型和理由
- ✅ 儿童模式不能选成人故事
- ✅ 禁忌"雷"时方案不含雷声
- ✅ `source=rule`，理由1-2句中文
- ✅ 方案确认前校验白名单

### 🟡 成员3：梦境空间与声景创作

**后端工作范围**：

1. **场景配置 API**
   - `GET /scenes/current`：返回当前用户最新场景草稿或冻结版本
   - `POST /scenes/save-draft`：保存场景草稿
     - 输入：`SceneConfigDto`（含声源列表、位置、音量、空间类型）
     - 行为：
       - `lifecycle_status=draft` 时允许修改
       - `lifecycle_status=handed_off` 时拒绝
       - 若调整已冻结版本 → 生成新版本（`config_version+1`）
   - `POST /scenes/freeze`：
     - 校验：至少有一个启用声源，所有声源可解析
     - 行为：`lifecycle_status=handed_off`，写入 `handed_off_at`
     - 冻结后整份聚合只读

2. **坐标系统**（必须使用归一化坐标）：
   - 范围：`0.00000 – 1.00000`
   - 原点：画布左上角
   - X：向右递增
   - Y：向下递增
   - 室内外共用同一坐标系，由声源的 `space_type` 区分

3. **声源参数**（对应 `SceneAudioSourceDto`）：
   - `assetId`：引用模块1的声音素材 UUID
   - `space`：indoor / outdoor
   - `x`, `y`：归一化位置（0.04-0.88, 0.08-0.82 有效区）
   - `volume`：0.000-1.000
   - `enabled`：true/false

4. **版本化规则**：
   - 新建场景：`scene_family_id=新UUID`，`config_version=1`
   - 调整已冻结版本：沿用 `scene_family_id`，新建 `scene_config_id`，`config_version=旧+1`
   - `previous_version_id` 指向直接前版
   - **已冻结版本禁止修改**

**数据库表**：
- `scene_config`（场景配置聚合根）
- `scene_element`（场景元素，可选）
- `scene_audio_source`（场景声源）

**禁止事项**：
- ❌ 不重新分析用户情绪
- ❌ 不修改助眠方案
- ❌ 不执行播放
- ❌ 不记录睡眠会话
- ❌ 不把已冻结场景原地改写

**验收标准**：
- ✅ 切换室内外不丢失已选声源
- ✅ 保存草稿后 `lifecycle_status=draft`
- ✅ 冻结后 `lifecycle_status=handed_off`，不能再修改
- ✅ 调整已冻结场景生成新版本
- ✅ 输出 `SceneConfigDto` 通过前端契约校验

### 🟠 成员4：睡眠模式与夜间记录

**后端工作范围**：

1. **会话管理 API**
   - `POST /sessions/start`：开始睡眠会话
     - 校验：方案状态=`confirmed`，场景状态=`handed_off`
     - 创建 `sleep_session`（状态=`preparing`），编排播放阶段
     - 发布 `PlanStartedFact`（事件，供模块5消费）
   - `POST /sessions/pause`：`status=paused`，暂停计时
   - `POST /sessions/resume`：`status=running`，恢复计时
   - `POST /sessions/stop`：
     - 计算 `active_playback_sec`（排除暂停时间）
     - 写入 `ended_at` 和 `stop_reason`
     - 终态：`completed`（定时完成）/ `cancelled`（用户退出）

2. **播放阶段编排**：
   - 根据 `SleepPlan.type` 编排阶段顺序：
     ```
     breath → story → soundscape → fade_out
     ```
   - 每阶段创建 `playback_stage` 记录

3. **播放事件记录**（只追加 `playback_event`）：
   - `session_preparing`：开始准备
   - `session_started`：真正开始播放
   - `stage_started` / `stage_completed`：阶段开始/完成
   - `story_finished`：故事结束后，关闭人声轨
   - `fade_started` / `fade_completed`：渐弱开始/完成
   - `paused` / `resumed`：暂停/恢复
   - `session_ended`：会话结束

4. **会话查询 API**
   - `GET /sessions/{id}`：会话详情
   - `GET /sessions/history`：历史会话列表（用于档案页）

**关键约束**：
- `active_playback_sec` **不是睡眠时长**，只是播放时长
- 不能写 `asleep_at`、`sleep_duration` 等无证据字段
- `stop_reason` 只能是：`timer_completed` / `user_ended` / `app_interrupted` / `audio_engine_error` / `validation_failed`
- 无授权时不采集噪声，不保存原始录音

**禁止事项**：
- ❌ 不调用 AI
- ❌ 不修改方案或场景
- ❌ 不计算睡眠质量
- ❌ 不把播放时长称为睡眠时长
- ❌ 不更新偏好和积分

**验收标准**：
- ✅ 非确认方案拒绝启动（返回 `validation_error`）
- ✅ 暂停时 `paused_sec` 同步累加
- ✅ 故事结束后只留环境声
- ✅ 渐弱音量单调下降到 0
- ✅ 所有终态都有正确的 `stop_reason`

### 🔴 成员5：次日反馈与个性化成长

**后端工作范围**：

1. **反馈提交 API**
   - `POST /feedback`：提交次日反馈
     - 输入：`MorningFeedbackDto`（入睡容易程度、声音舒适度、下次人声偏好、补充说明）
     - 校验：`session_id` 未提交过（幂等）
     - 行为：
       - 写入 `morning_feedback`
       - 更新 `preference_profile`（只更新本次明确表达的偏好）
       - 追加 `points_ledger`（`feedback_submitted` 事件，+10分）
   - `GET /feedback/{sessionId}`：查询某会话是否已反馈

2. **偏好管理 API**
   - `GET /preferences`：返回当前用户偏好画像
     - 人声偏好、禁忌声音标签、偏好故事主题、偏好呼吸模板、偏好场景
   - `PUT /preferences`：更新偏好（用户主动设置）

3. **积分 API**
   - `GET /points/entries`：积分流水（分页）
   - `GET /points/balance`：当前余额
   - 积分规则：
     | 事件 | 积分 | 幂等键 |
     |---|---|---|
     | 按计划开始 | +5 | `points:{userId}:plan_started:{planId}` |
     | 提交反馈 | +10 | `points:{userId}:feedback_submitted:{feedbackId}` |

4. **偏好画像更新逻辑**（`PlanStartedFact` 事件处理）：
   - 模块4发布 `PlanStartedFact` 后，模块5消费并追加 `plan_started` 积分
   - 同一会话只计一次（幂等）

5. **报告数据查询**（读模型，不建核心表）：
   - `GET /reports/summary`：返回近期报告
     - 播放记录（来自模块4，按 `record_source=playback_record`）
     - 主观反馈（来自 `morning_feedback`，按 `record_source=subjective_feedback`）
     - 两种来源分开展示，不合并为综合评分

**数据库表**：
- `morning_feedback`
- `preference_profile`
- `preference_forbidden_sound_tag`
- `preference_story_theme`
- `preference_breath_template`
- `preference_scene`
- `points_ledger`

**关键约束**：
- 一个会话最多一条反馈（幂等键唯一）
- 积分只追加，不扣分
- 积分不读取播放时长、睡眠时长、深睡、连续签到
- 反馈必须带 `record_source=subjective_feedback`
- 报告数据保留来源标签，不合成无来源结论

**禁止事项**：
- ❌ 不重新定义睡眠会话
- ❌ 不修改历史播放事件
- ❌ 不用播放时长推断睡眠时长
- ❌ 不用设备摘要覆盖主观反馈

**验收标准**：
- ✅ 重复提交不重复发积分
- ✅ 只更新本次明确表达的偏好
- ✅ 报告每项有来源标签
- ✅ 无反馈时不生成主观评价

## 六、统一团队约束

### 6.1 禁止规则（任何人不得违反）

1. ❌ **禁止跨模块直接调用**：模块2不能直接读模块1的数据库表，只能通过 `ContentCatalogPort`
2. ❌ **禁止修改公共契约**：DTO、Port、枚举的定义只能由组长修改
3. ❌ **禁止保存对话原文**：用户说的话不能存进数据库
4. ❌ **禁止写睡眠时长字段**：`asleep_at`、`sleep_duration`、`deep_sleep` 等字段永远不能出现
5. ❌ **禁止把播放时长称为睡眠时长**：前端和后端所有展示都不能这么写
6. ❌ **禁止未审核内容进入播放链路**：故事必须 `review_status=approved`
7. ❌ **禁止保存明文 PIN**：只存哈希
8. ❌ **禁止用播放时长发积分**：积分只能因"开始计划"或"提交反馈"而加
9. ❌ **禁止在未获授权时采集数据**：噪声、原始录音等必须有独立授权
10. ❌ **禁止跨模块修改对方数据**：模块3不能改模块2的方案，模块4不能改模块3的场景

### 6.2 代码规范

- **命名**：数据库表用蛇形（`sleep_session`），API 字段用驼峰（`sessionId`）
- **时间**：统一存 UTC，字段后缀 `_at`
- **时长**：统一用秒（整数），字段后缀 `_sec`
- **UUID**：所有主键用 UUID，不自增
- **错误响应**：
  ```json
  {
    "error": "validation_error",
    "message": "方案尚未确认，无法启动播放",
    "code": "PLAN_NOT_CONFIRMED"
  }
  ```

### 6.3 沟通规范

| 场景 | 做法 |
|---|---|
| 发现契约不够用 | 提交"契约变更申请"，等组长批准后再改 |

### 6.4 禁止的 PR 类型

- ❌ 把其他成员模块的代码复制过来
- ❌ 用 JSON 代替关系型表（多值偏好等关键字段）
