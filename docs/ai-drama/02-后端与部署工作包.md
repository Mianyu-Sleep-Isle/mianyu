## 9. 接口实现

下面只写契约里没有展开的服务端行为。请求和响应的字段以契约 §5、§6 为准，一个字段都不能少，标了 `| null` 的要返回 `null` 而不是省略。

### 9.1 公共门禁

除 `GET /drama/media/...` 外，每个接口：

1. `requireUserId`。没有头 → `401 IDENTITY_REQUIRED`。
2. 读 `user_profile.age_mode`，不读 `X-Age-Mode`。`child` 时：`GET /drama/capabilities` 仍返回 200 且 `age_mode_allowed=false`；其它接口 `403 DRAMA_CHILD_MODE_FORBIDDEN`。
3. `DRAMA_ENABLED` 不是 `1` 时，写接口返回 `503 DRAMA_DISABLED`。`capabilities.enabled=false`。

危机词在调用模型之前检查用户文本（对话消息、以及创建任务时的 `theme` / `setting` / `protagonist` / `forbidden_elements`）。命中「自杀」「不想活」「伤害自己」「结束生命」时返回 `400 PRODUCT_BOUNDARY_CRISIS`，不调用模型，不写库，不打正文日志。

### 9.2 `GET /drama/capabilities`

不要为了这个接口调用 `/chat/completions`。`llm` 的判断：

| 条件 | 值 |
|---|---|
| `DRAMA_PROVIDERS=fake` | `ready` |
| `drama_gpu_lock.job_id` 非空，或存在 `running` 且阶段是 `generating_story` / `reviewing` / `generating_storyboard` 的任务 | `busy` |
| `GET ${LLM_BASE_URL去掉 /v1}/health` 在 2 秒内不是 200 | `down` |
| 其它 | `ready` |

健康检查结果缓存 5 秒。`media_pipeline`：fake 模式为 `ready`；real 模式下 ffmpeg 可执行且 TTS `/health` 正常为 `ready`，只有 ffmpeg 正常为 `degraded`，ffmpeg 不存在为 `down`。ComfyUI 没启动时不算 `down`，因为它本来就是按需启动。

`queue_length` = `status IN ('queued','running','cancelling')` 的行数。`active_job_id` = 当前用户这种行里最新的一条，没有则 `null`。

### 9.3 `POST /drama/chat` 和 `POST /drama/brief`

Zod：

- `messages`：1～11 条；`role` 交替；第一条和最后一条都是 `user`；`user` 内容 1～300 字；`assistant` 内容 1～600 字。
- `user` 条数大于 6 → `400 DRAMA_CHAT_ROUND_LIMIT`。
- 同一用户 `chat` + `brief` 合计，滚动 60 秒内超过 10 次 → `429 DRAMA_RATE_LIMITED`。计数放内存，重启清零即可。
- `guide_state` 允许 `null`。服务端不信任它，只把它作为提示写进 prompt。

`llm=busy` 或 `down` 时不要调用模型，直接 `503 LLM_UNAVAILABLE`，`details: [{ "reason": "busy" | "down", "retry_after_sec": 30 }]`。

对话请求 `max_tokens=400`，服务端 50 秒中止。摘要请求 `max_tokens=800`，服务端 70 秒中止。两处中止都返回 `503 LLM_UNAVAILABLE`（`reason=down`）。前端超时分别是 60 秒和 90 秒，服务端先失败，前端拿到的就是契约里的错误包络，而不是网络超时。

对话模型只产出下面的 JSON。`missing`、`ready`、`round`、`rounds_left` 由服务端算：

```json
{
  "reply": "不超过 80 字，只问一个问题",
  "theme": "string 或 null",
  "mood": "calm|warm|healing|dreamy 或 null",
  "setting": "string 或 null",
  "protagonist": "string 或 null",
  "visual_style": "watercolor|paper_cut|soft_anime|oil_pastel 或 null",
  "forbidden_elements": ["不超过 12 字"],
  "suggestions": ["不超过 8 字，最多 3 个"]
}
```

服务端覆盖规则：

- 字符串 `trim` 后按契约 §5.2 的长度截断。空字符串改 `null`。
- `mood`、`visual_style` 不在枚举内就改 `null`。
- `missing` = `theme`、`mood`、`setting` 里仍为 `null` 的项，保持这个顺序。
- `ready = (missing.length === 0)`。
- 第 6 轮如果还有缺口：`mood` 补 `calm`，`setting` 补「安静的小屋」，`theme` 仍空则补「一个安静的小故事」，然后 `ready=true`，`reply` 若还在提问就改成「这些就够了，可以生成故事了。」
- `suggestions` 最多 4 个（模型给 3 个，服务端可以不追加）。每个截断到 10 字。

`POST /drama/brief` 用同一套消息校验。模型产出契约 §5.3 的 `brief`，然后服务端强制：

- 缺的 `visual_style` → `watercolor`；缺的 `duration_sec` → `120`；缺的 `shot_count` → `6`；`voice_id` 固定 `default`。
- `theme`、`setting`、`protagonist` 任一最终为空 → `422 DRAMA_BRIEF_INCOMPLETE`，`details: [{ "field": "theme" }]`。
- 再跑 §11 的确定性词表。命中 → `422 DRAMA_BRIEF_UNSAFE`。
- `privacy_replacements` 只保留模型给出的说明短句（每条 ≤ 40 字，最多 5 条）。如果用户原文里有手机号（`1\d{10}`），服务端追加「电话号码已从故事里去掉」，并且不把号码写进 `brief` 的任何字段。

这两个接口都不写数据库。

### 9.4 `POST /drama/jobs`

1. 没有 `Idempotency-Key` → `400 IDEMPOTENCY_KEY_REQUIRED`。键最长 80 字符。
2. 用 Zod 按契约 §5.3 校验 `brief`。`forbidden_elements` 去空白、去重，超过 10 项或单项超过 12 字 → `400 INVALID_REQUEST`。
3. 词表和危机词再查一次。
4. 同一用户、同一幂等键已有任务 → `200` 和当时的 `DramaJobDto`，不比较请求体。
5. 该用户已有 `queued|running|cancelling` 任务 → `409 DRAMA_JOB_ALREADY_RUNNING`，`details: [{ "job_id": "..." }]`。
6. 全局这类任务 ≥ 3 → `503 DRAMA_QUEUE_FULL`。
7. 插入任务：`status=queued`，`stage=null`，`progress=0`，`seed` 为随机 31 位正整数，7 个阶段为 `pending`。返回 `202`。

### 9.5 查询、取消、重试、删除

- `GET /drama/jobs/{jobId}` 只读 SQLite，不调用任何模型。不是该用户的 id 返回 `404 DRAMA_JOB_NOT_FOUND`。
- `queue_position`：仅 `queued` 时计算，值为「创建时间更早的 queued 行数 + 1」。
- `can_cancel`：`queued` 或 `running`。`can_retry`：`failed` 且 `error_retryable=1` 且 `manual_retry_count < 3`。
- `thumbnail_url`：该镜头 `image_status=completed` 时，签一个 `thumb-00N.jpg` 的 URL，否则 `null`。
- 取消：`queued` 直接 `cancelled`。`running` 改为 `cancelling`。worker 在每个阶段开始前、每张图开始前检查，看到 `cancelling` 就停止新推理，把状态写成 `cancelled`，已写好的文件保留。其它状态 `409 DRAMA_JOB_INVALID_STATE`。
- 重试：只允许 `failed`。`manual_retry_count += 1`，`status` 回到 `queued`，`stage` 保持 `failed_stage`，该阶段的 `drama_stage.status` 改回 `pending`，已 `completed` 的阶段不动。超过 3 次 `409 DRAMA_RETRY_LIMIT`。
- 删除：非终态 `409`。终态删除行和目录，返回 `{ "data": { "deleted": true } }`。
- `GET /drama/jobs/{jobId}/result`：不是 `completed` 就 `409 DRAMA_RESULT_NOT_READY`。每次调用都重新签名，`media_expires_at = now + MEDIA_URL_TTL_SEC`。

`DramaJobDto.stages` 永远 7 项，顺序固定。`shots` 在分镜阶段完成前是 `[]`，完成后长度等于 `brief.shot_count`。

### 9.6 媒体

```ts
const FILE_NAME = /^(final\.mp4|cover\.jpg|subtitles\.vtt|character\.png|shot-\d{3}\.jpg|thumb-\d{3}\.jpg)$/;
```

先用这个正则校验 `fileName`，再 `path.join(jobDir, fileName)`。不接受子目录。

```ts
sig = createHmac('sha256', MEDIA_SIGNING_SECRET).update(`${jobId}/${fileName}:${exp}`).digest('hex')
```

`exp` 是十进制 unix 秒。用 `timingSafeEqual` 比较签名。缺少、错误或过期都返回 `403 MEDIA_LINK_EXPIRED`。文件不存在返回 `404 MEDIA_NOT_FOUND`。两者都是 JSON 错误包络。

`final.mp4` 支持 `Range`，响应 `206` 和 `Accept-Ranges: bytes`。Express `send` 默认支持 Range，直接用即可。响应头 `Cache-Control: private, max-age=3600`。

示例作品的 `job_id` 是 `showcase-01` 这种固定字符串，文件放在 `DRAMA_SHOWCASE_DIR/showcase-01/`，签名规则相同。`GET /drama/showcase` 至少返回这一条，`is_showcase=true`。目录不存在时返回空数组会让联调第 12 项失败，所以部署检查要把这个目录当成启动条件。

### 9.7 重画单张（P1）

B5 完成前，这个路由返回 `501`，错误码 `NOT_IMPLEMENTED`。不要返回 404，否则前端无法判断该隐藏按钮。

## 11. 审核与模板

两层都在 `reviewing` 阶段做。

**确定性层**（故事、分镜、英文提示词都要查）：

- 字数不在 300～600，或分镜数不等于 `shot_count` → 不通过。
- 词表（子串）：杀人、血腥、鬼魂、尸体、色情、裸体、自杀、恐怖、惊吓、自残。
- `forbidden_elements` 的每一项出现在正文或 `image_prompt` 里 → 不通过。
- 医疗承诺子串：治愈失眠、治疗失眠、诊断。

**语义层**：温度 0.1 的审核提示词。`approved=false` 或 `risk_tags` 非空都算不通过。

不通过时，把 `rewrite_advice` 和失败原因发给故事提示词重写，最多 2 次，每次都重跑两层。仍不通过就使用模板，不把失败正文交给后续阶段。

模板放在 `templates.ts`，至少两条，结构与审核通过的故事 + 分镜相同。`story_source=template`，`notices` 追加 `STORY_TEMPLATE_FALLBACK`，故事、审核、分镜三个阶段都记 `completed`。模板正文也要能通过确定性词表。

模板一（主题含「灯塔」或「猫」时优先；否则用模板二）：

- 标题：灯塔里的雨声
- 简介：小橘猫南瓜在灯塔顶层听着细雨，慢慢睡着了。
- 正文要自己写成 360～420 个汉字，内容只包含：橘猫南瓜、灯塔顶层、细雨、毛毯、灯光、睡着。不要加情节冲突。
- 6 个镜头的 `narration_text` 把正文顺序切开；`image_prompt` 用 §10 的水彩前缀；`camera_motion` 依次 `static`、`zoom_in`、`pan`、`static`、`zoom_out`、`static`。

模板二：森林小屋里的热牛奶，同样 6 镜，主角是一只小兔子。

两条模板的正文写死在代码里，保证没有模型时审核降级仍然可用。

## 12. Worker 与阶段预算

`worker.ts` 单线程循环：每 2 秒领取 `created_at` 最早的 `queued` 任务。没有任务就继续睡。不要开第二个 worker。

领取时把 `queued` 改成 `running`。若 `stage` 为 `null`，从 `generating_story` 开始；重试时从当前 `stage` 开始。

每个阶段开始前：

1. 若任务已是 `cancelling`，写成 `cancelled` 并释放 GPU 锁，返回。
2. 把该阶段写成 `running`，`attempt += 1`。
3. 按 §13 准备 GPU。
4. 执行。成功则写成 `completed`，进入下一阶段。
5. 失败则 `stage_detail=retrying`，同一阶段最多再自动试 2 次（共 3 次）。耗尽后：故事阶段走模板；角色图走预置图；单张分镜图只重试该张；旁白走预置静音兜底（见 §15）。这些兜底都用完仍失败，才把任务写成 `failed`，`failed_stage` 为当前阶段，`error` 用下表。

| 阶段 | 超时 | 失败码 | 兜底 |
|---|---|---|---|
| `generating_story` | 180 秒 | `MODEL_OUTPUT_INVALID` 或 `LLM_UNAVAILABLE` | 模板 |
| `reviewing` | 每轮 60 秒 | 同上 | 重写 2 次后模板 |
| `generating_storyboard` | 120 秒 | `MODEL_OUTPUT_INVALID` | 模板自带分镜 |
| `generating_character_reference` | 模型加载 120 秒，出图 180 秒 | `IMAGE_GENERATION_FAILED` / `GPU_STAGE_TIMEOUT` / `GPU_SERVICE_UNAVAILABLE` | 复制 `deploy/assets/character-preset.png`，notice `CHARACTER_PRESET_FALLBACK` |
| `generating_images` | 每张 180 秒 | 同上 | 该张换种子重试 2 次；仍失败则整阶段失败。某张重试成功时 notice `SHOT_IMAGE_RETRIED` |
| `synthesizing_voice` | 每段 90 秒 | `TTS_GENERATION_FAILED` | 该段换用 8 秒预置静音 wav，三段以上失败才让阶段失败 |
| `composing_video` | 180 秒 | `VIDEO_COMPOSITION_FAILED` | 无兜底，保留中间文件 |

`review_status` 不是 `approved` 时，worker 禁止进入 `generating_storyboard` 之后的任何阶段。模板路径必须先把 `review_status` 写成 `approved`。

进度按契约 §4.6 写入 `drama_job.progress`，只增不减：

```text
权重 = story 10, reviewing 5, storyboard 5, character 10, images 40, voice 15, video 15
progress = 已完成阶段权重之和 + floor(当前阶段权重 × done / total)
```

图片阶段 `done` 是 `image_status=completed` 的张数，`total` 是 `shot_count`。旁白阶段看 `audio_status`。其它阶段完成前 `done=0`。`completed` 时写 100。

进程启动时的恢复：

- `running` 改回 `queued`，`stage` 不变，已完成的阶段保留。
- `cancelling` 改成 `cancelled`。
- GPU 锁的 `heartbeat_at` 超过 120 秒就清空锁。
- 不因为重启本身写成 `JOB_INTERRUPTED`。只有恢复后发现该阶段产物文件缺失，才写成 `failed` / `JOB_INTERRUPTED` / `retryable=true`。

`GET` 进度接口不走这段逻辑，所以轮询不会被 GPU 堵住。

## 13. GPU 调度

`gpu-supervisor.ts` 只允许下面几个动作，参数全部写死在数组里：

| 动作 | 命令 |
|---|---|
| 停 Qwen | `supervisorctl -c $SUPERVISOR_CONFIG stop llamacpp` |
| 起 Qwen | `supervisorctl -c $SUPERVISOR_CONFIG start llamacpp` |
| 停 ComfyUI | `supervisorctl -c $SUPERVISOR_CONFIG stop comfyui` |
| 起 ComfyUI | `supervisorctl -c $SUPERVISOR_CONFIG start comfyui` |
| 看显存 | `nvidia-smi --query-gpu=memory.used --format=csv,noheader,nounits` |

Qwen 的启动参数不要在这个文件里重写。第一次上机时执行 `ps -ef | grep llama`，把现有参数原样抄进 supervisord 的 `llamacpp` 程序，只改两处：`--host 127.0.0.1` 和 `--port 8081`。必须保留的语义：模型路径 `/hy-tmp/Qwen3.8-27B-UD-Q8_K_L.gguf`、`--api-key` 从环境变量读、`n_ctx 131072`、Flash Attention、MTP draft 最多 4 个、槽位 1。

绘图阶段的切换顺序：

1. `drama_gpu_lock` 写成当前 `job_id` 和阶段，之后每 15 秒更新 `heartbeat_at`。
2. `stage_detail=waiting_gpu`，停止 `llamacpp`。
3. 最多等 90 秒，直到两张卡 `memory.used` 都小于 1500 MiB。超时 → `GPU_STAGE_TIMEOUT`。
4. `stage_detail=loading_model`，启动 `comfyui`，最多等 120 秒直到 `GET /system_stats` 返回 200。失败 → `GPU_SERVICE_UNAVAILABLE`。
5. 出图。全部镜头结束后停止 `comfyui`，再等显存降下来。
6. 启动 `llamacpp`，最多等 180 秒直到 `GET http://127.0.0.1:8081/health` 返回 200。
7. 清空 GPU 锁。即使出图失败，也要执行 5～7，不能把 Qwen 留在停止状态。用 `try/finally`。

故事、审核、分镜、旁白、合成都不停 Qwen。旁白和合成可以在 Qwen 运行时进行。

fake 模式的 supervisor 是空实现，不执行命令。

## 15. 旁白

`services/tts/server.py` 使用 **Fun-CosyVoice3-0.5B**，设备固定 CPU。只暴露两个接口：

```text
GET  /health                     -> 200 {"status":"ok"}
POST /tts                        -> 200 audio/wav
     {"text":"……","voice_id":"default"}
```

音色只用模型自带的 zero-shot 示例音频，复制为 `services/tts/voices/default.wav`。不提供克隆接口，不接收用户上传的音频。

`requirements.txt` 锁住实际能跑通的版本。服务只监听 `127.0.0.1:9880`。

Node 侧按镜头调用，把返回的 wav 存成临时文件，再用 ffmpeg 转成 44100Hz 单声道。某个镜头失败：重试 2 次，再失败就生成一段与该镜头等长的静音 wav（ffmpeg `anullsrc`），并记日志。同一任务里这种静音镜头达到 3 个，阶段才失败，错误码 `TTS_GENERATION_FAILED`。

TTS 的输入只能是 `drama_shot.narration_text`。不允许把 `messages` 传进来。

## 16. 视频合成

用系统 ffmpeg，不新增 npm 包。每一镜先做成一段无声画：

```text
ffmpeg -y -loop 1 -i shot-00N.jpg -vf "
  scale=720:1280:force_original_aspect_ratio=increase,crop=720:1280,
  zoompan=z='Z':x='X':y='Y':d=FRAMES:s=720x1280:fps=30,
  fade=t=in:st=0:d=0.4,fade=t=out:st=OUT:d=0.4,
  format=yuv420p
" -t DURATION -r 30 -an clip-00N.mp4
```

`FRAMES = round(duration_sec * 30)`，`OUT = duration_sec - 0.4`。`zoompan` 的表达式：

| `camera_motion` | `z` | `x` / `y` |
|---|---|---|
| `static` | `1` | 居中 |
| `zoom_in` | `min(1.08,1+0.0006*on)` | 居中 |
| `zoom_out` | `max(1,1.08-0.0006*on)` | 居中 |
| `pan` | `1.05` | `x=(iw-iw/zoom)*on/FRAMES`，`y` 居中 |

把每段旁白 `apad` 或 `atrim` 到和画面一样长，再和画面合成。各镜用 concat demuxer 拼起来。环境声使用仓库里已有的 `assets/audio/indoor/A07_room_tone_night.mp3`，`-stream_loop -1`，`volume=0.15`，与旁白 `amix`，后面加 `alimiter`。

最终编码：

```text
-c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -r 30
-c:a aac -b:a 128k -ac 2 -ar 44100
-movflags +faststart
final.mp4
```

字幕：每个镜头一条 cue 的 `subtitles.vtt`（`WEBVTT`，时间用 `HH:MM:SS.mmm`）。另外写一份同内容的 `subtitles.srt`，用 ffmpeg `subtitles` 滤镜烧进画面。字体文件 `deploy/fonts/NotoSansSC-Regular.otf`，`FontSize=18`，底部居中，`MarginV=40`。字体文件缺失时跳过烧录，仍然输出 `subtitles.vtt`，并在日志里记一条 `subtitle_font_missing`。

`video_duration_sec` 用 `ffprobe` 读 `format.duration`，`video_size_bytes` 用文件大小。分辨率必须是 720×1280。

fake 模式不跑这套滤镜：把 `backend/fixtures/drama/tiny.mp4` 复制为 `final.mp4`，并写一个 2 秒的 vtt。`tiny.mp4` 用下面的命令生成后提交：

```text
ffmpeg -y -f lavfi -i color=c=0x0c2144:s=720x1280:d=2 -f lavfi -i anullsrc=r=44100:cl=mono -shortest -c:v libx264 -pix_fmt yuv420p -movflags +faststart -c:a aac tiny.mp4
```

## 19. Nginx 与 supervisord

`deploy/nginx.conf`：

```nginx
worker_processes 1;
error_log /hy-tmp/mianyu/logs/nginx-error.log warn;
pid /tmp/mianyu-nginx.pid;
events { worker_connections 128; }
http {
  include /etc/nginx/mime.types;
  access_log off;
  client_max_body_size 1m;
  server {
    listen 8080;
    # 原来的 Qwen。不要缓冲，避免流式输出被攒住。
    location /v1/ {
      proxy_pass http://127.0.0.1:8081;
      proxy_buffering off;
      proxy_read_timeout 300s;
    }
    location = /health {
      proxy_pass http://127.0.0.1:8081/health;
    }
    # 对话最长约 60 秒，网关读超时必须大于它。
    location /api/ {
      proxy_pass http://127.0.0.1:8787;
      proxy_read_timeout 120s;
    }
    location / {
      proxy_pass http://127.0.0.1:8787;
    }
  }
}
```

`deploy/supervisord.conf` 的程序：

| program | autostart | 说明 |
|---|---|---|
| `nginx` | true | `nginx -c /hy-tmp/mianyu/deploy/nginx.conf`
| `llamacpp` | true | 现有命令，端口改为 8081，`--host 127.0.0.1` |
| `tts` | true | `python server.py`，工作目录 `services/tts`，只监听 127.0.0.1 |
| `mianyu` | true | 在 `backend/` 下执行现有的 `node --env-file=/hy-tmp/mianyu/.env --experimental-transform-types src/server.ts`。环境里 `DRAMA_WORKER=1` |
| `comfyui` | false | `python main.py --listen 127.0.0.1 --port 8188 --cuda-device 0`，`autorestart=false` |

`mianyu` 的 `priority` 高于 `llamacpp` 和 `tts`，让模型先起来。全部程序 `stdout` 写到 `/hy-tmp/mianyu/logs/`。日志配置里不要打开命令行回显。

ComfyUI 和 TTS 的端口不要写到 Nginx 里。

## 20. 上线步骤

切换端口会重启现在占用 8080 的 llama-server。开始前在群里确认机器空闲，避免打断别人正在跑的任务。

1. 把本分支同步到 `/hy-tmp/mianyu/app`。数据、模型和 `.env` 放在 `/hy-tmp/mianyu/`，不放在会随代码覆盖的目录。
2. `npm --prefix backend install`。确认 `node -v` 是 24.x。
3. 安装 ffmpeg、Nginx、supervisor、ComfyUI 和 §14 的模型文件。`python services/tts/server.py` 先单独跑通 `POST /tts`。
4. 记录现有 llama 命令行，写进 supervisord，端口改为 8081。
5. 停掉现在的 llama-server。启动 supervisord。
6. 验收 Qwen 没被切坏：

```text
curl -s http://127.0.0.1:8081/health
curl -s -H "Authorization: Bearer $LLM_API_KEY" http://127.0.0.1:8081/v1/models
curl -s -H "Authorization: Bearer $LLM_API_KEY" http://i-1.gpushare.com:54336/v1/models
```

三条都应成功，模型 id 为 `Qwen3.8-27B`。公网不带密钥应仍是 401。

7. `curl -s http://i-1.gpushare.com:54336/api/v1/health` 返回 `mianyu-backend`，`migrations` 数组含 `600`。
8. `curl -s http://i-1.gpushare.com:54336/api/v1/health` 已经在第 7 步验收。短片接口也用 curl 验收，不要用浏览器页面代替 Flutter。
9. 生成 `showcase-01`。然后停掉 `comfyui` 和 `tts`，确认 `GET /drama/showcase` 仍返回视频 URL，且 URL 能播放。
10. 把示例媒体发给 A，约时间按契约 §10 做联调。

本地开发不需要这套切换：`DRAMA_PROVIDERS=fake DRAMA_WORKER=1 npm --prefix backend run dev`。Flutter 用 `flutter run --dart-define=MIANYU_API_BASE=http://127.0.0.1:8787/api/v1`。

## 21. 测试

`drama.test.ts` 用 fake 提供者，至少覆盖：

1. 儿童模式调用 `POST /drama/chat` 得到 403；`GET /drama/capabilities` 得到 `age_mode_allowed=false`。

8. `running` 时取消，后续阶段的 provider 不再被调用。
9. 把进程中的 `running` 任务按启动恢复规则处理，阶段不倒退。
10. `DELETE /api/v1/users/me/data` 之后，该用户任务行和目录都没有了。
