# 自然声接入与操作说明

## 一 打开和检查

1. 解压 `成员一后端文件交付包.zip`，直接查看其中的说明、清单、assets、config 和 tools；保持这些内容之间的目录关系。
2. 打开 `声音素材清单.csv` 查看全部候选；按 `originalFilename` 追溯源文件。
3. 在本机用播放器打开 `assets/audio/` 中的 MP3 做素材听审。此本地检查与生产接口的授权校验是两个步骤；不要把待审核素材当作已发布内容。
4. 如有 Python 3，在本目录运行 `python tools/检查文件完整性.py`。成功将输出 19 条素材及全部检查通过信息。

## 二 元数据字段

|字段|含义|
|---|---|
|soundCode|设计中的声音展示编号，如 A01；不能作为数据库 UUID 主键|
|variantId|候选文件编号，如 A01-01|
|assetId / contentId|固定 UUID，两字段相同；依据类别和原始文件 SHA-256 确定性生成|
|name / title|可读名称；title 对应 API 标题|
|category|声音分类名称|
|spaceType|indoor 或 outdoor；A02 固定 indoor，其余按素材初分 outdoor|
|resourceKey|相对资源键，例如 audio/A01/A01-01_小雨.mp3|
|resourceAddress|本交付包根目录下路径，例如 assets/audio/A01/A01-01_小雨.mp3；不是公网播放地址|
|durationSec|实际音频帧时长，秒，可含小数，不是用户方案时长|
|format / codec|实际格式 MP3 与 MPEG Layer III|
|sizeBytes / sha256|原文件字节大小与完整性哈希|
|sampleRatesHz / channels / bitratesKbps|检测到的参数集合，数组适配可变码率|
|isDefaultCandidate|审核前的默认候选，每个非 A12 类别一条|
|isDefault|当前实际默认状态，本包全部 false|
|recommendationCandidate|是否属于后续可审核的推荐候选，不能直接决定推荐|
|allowRecommendation / enabled|当前是否允许推荐及启用，本包全部 false|
|exclusionTestOnly / purpose|排除测试标识及用途|
|copyrightStatus / licenseEvidence|版权待审核状态；没有凭证时为 pending_review / null|
|ageMode / ageReviewStatus|初始 adult 范围及待审标记；不是已完成年龄适用性审核|
|tags / classificationBasis|按原目录、文件名添加的保守标签；未完成听审|
|sourceArchiveEntry / originalFilename|原 ZIP 条目及文件名，可反查全部音频|

`isDefaultCandidate`、`recommendationCandidate`、用途及其他审核扩展字段属于本包清单字段，不是擅自新增到冻结 API 的 DTO。不要直接将整条元数据返回客户端。

## 三 对应实际后端规范

依据源包 `backend-team/00-统一团队约束.md` 第 1、3、6 节：UUID 业务主键、camelCase JSON、秒单位及版权六值；`01-HTTP-API-v1.md` 第 3 节：内容列表、详情与 resolve；`02-成员1-内容中心后端.md` 的资源地址策略与种子约定；`03-成员2-沟通与方案后端.md` 的禁忌硬过滤。设计说明第 3 节要求声音编号、名称、分类、资源地址、时长与试听，本包全部覆盖这些数据字段。

已存在的接口：

- `GET /api/v1/content?kind=audio&space=indoor|outdoor`
- `GET /api/v1/content/:contentId`
- `POST /api/v1/content/:contentId/resolve`
- 模块1公开服务 `getPlayableContent(contentId, userContext)`
- 模块2 `POST /api/v1/plans/compose`，通过 `selectedContentIds` 引用 UUID。

文档给出接口和业务约定，但未附实际 `audio_asset` DDL 或完整 resolve 响应结构。因此 `后端导入数据.json` 是独立导入适配数据，不能假定可原样导入某张已有表；也不伪造完整 HTTP 响应。`音频详细信息.json` 是保留扩展信息的通用 JSON 清单。

## 四 在团队工程中接入

1. 将本包 `assets/audio/` 内容复制至实际工程的 `assets/audio/`，保留 Axx 子目录。不要修改同步的原始参考附件。
2. 成员1的 `seed.ts` 读取 `后端导入数据.json` 中 `audioAssets`，使用团队实际 repository 以 `assetId` 执行 upsert；重复运行不能新增相同素材。若数据库列名为 snake_case，显式映射 `assetId→asset_id`、`durationSec→duration_sec`、`resourceKey→resource_key`，其余以真实 DDL 为准，不能猜造 SQL 表结构。
3. 把 `soundCode` 和 UUID 的映射作为展示编号关联；成员3 `assetId` 与成员2/4 `contentId` 都指向同一个 UUID。不要将 A01 直接传作 UUID。
4. 扩展默认和排除策略可以从清单读取，或通过团队约定的 schema 扩展保存；冻结 DTO/公共表发生变化时按团队变更流程处理。
5. 列表仅输出现有 DTO 字段（`contentId/kind/title/subtitle/durationSec/spaceType/ageMode/coverUrl/previewAvailable/favorited`）；本包没有封面，不填不存在的图片地址。封面缺省行为按真实 schema 决定。`favorited` 取当前用户实际收藏；不可永久硬编码。未通过校验的素材应被过滤，不能以 `previewAvailable=true` 假装可试听。
6. resolve 在校验年龄、版权和 enabled 后把 `resourceKey` 解析成播放地址。数据库不保存本机绝对路径、临时下载地址或公开 URL。当前全部待审核，所以正常列表为空、resolve 拒绝是预期结果。
7. 补齐授权凭证、年龄和完整试听审核后，才可启用合格的非 A12 素材，设置 `allowRecommendation=true`；确认合适后将预选项设为 `isDefault=true` 并同步资源映射的默认 UUID。人工审核若不通过，可另选同类候选；不得伪造通过状态。

本包没有可直接执行的数据库迁移或 HTTP 服务，因为未提供工程实现。完成以上步骤后应在真实工程执行其迁移、类型检查、测试及接口联调；本包完整性检查不能替代这些工程验收。

## 五 排雷规则与验收

生产候选条件应同时满足：素材已启用、版权允许、年龄规则通过、允许推荐、非测试专用，且标签与用户禁忌无交集。用户显式传入 `selectedContentIds` 也要重新校验，不能跳过规则。

“不要打雷”映射到 `thunder` 是本包的本地接入约定；后端文档只固定 `avoidTags` 为字符串数组，未给出完整标签字典。`EXCLUSION_TEST_ONLY` 是本包建议的稳定原因码，需纳入真实工程错误码映射，不能声称它已是冻结 API 的既有错误码。

A12 无条件禁止生产启用、默认或推荐，且应拒绝生产 resolve。即使没有传入禁雷标签，或被用户显式选中，也必须排除。测试时用独立测试夹具验证 `thunder` 禁忌过滤，不要为测试在生产中临时开放远雷。对其他素材听审发现雷声时同样添加 `thunder` 并禁止进入禁雷方案。

真实工程应验证：A02 仅在室内分类出现；未审核素材被过滤；重复导入 UUID 不变且不重复；原始资源键无本机绝对路径；19 条素材一一可追溯；A12 的四个 UUID 在默认、推荐和显式选择三个路径均被拒绝；通过授权审核的非 A12 素材能够经 resolve 播放；文件损坏或不存在时明确返回错误。
